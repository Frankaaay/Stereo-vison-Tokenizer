# H100 服务器使用指南

> 适用账号：`hezhou`。本文中的个人开发位置、目录、数据和资产约定不作为其他用户的默认值。

本文面向 Stereo-vison-Tokenizer 项目组。H100 由 Slurm 统一调度；节点数量、GPU、QOS、容量、软件版本和资源状态均为易变事实，必须实时查询。本文不构成安装、远端修改、提交或取消作业、训练、评估、预处理、删除或扩大资源规模的授权。

## 1. 登录与实时快照

连接参数只保存在本机 `~/.ssh/config` 或受控凭据存储中。组员使用各自账号，不在仓库中固定用户名、地址、端口或密钥。

```powershell
ssh.exe h100
```

登录后先做只读检查：

```bash
whoami
hostname
pwd
git --version
uv --version
sinfo -h -o "%P|%D|%G|%l"
squeue -u "$USER"
sacctmgr -n -P show qos format=Name,MaxWall,MaxTRESPU,MaxTRES
df -h /gpfs/jiuquyun
```

登录节点没有可供用户直接训练的 GPU。不要用登录节点上的 `nvidia-smi` 判断集群 GPU 是否可用，也不要在登录节点运行训练或重型 CPU/内存任务。

QOS 名称、GPU 上限和最长时间以 `sacctmgr`、`scontrol show job` 和 `sbatch --test-only` 的实时结果为准，不在指南中保存固定数字。

## 2. Stereo-vison-Tokenizer 工作流

- H100 是本项目默认开发环境；代码、脚本、配置、测试和文档在当前用户自己的 H100 clone 中修改和验证。
- 本地 Codex 仅通过 `ssh h100` 发起和管理操作，不在本地 clone 开发，也不假定固定登录用户。
- 在 H100 运行、修改、测试、训练、评估或预处理前，先检查 clean 状态，再执行 `git fetch origin` 和当前分支的 `git pull --ff-only`。
- 完成同步且获得当前任务授权后，才可在该 clone 修改；最小验证通过后再按授权 commit/push。
- 每次操作前核对当前用户、主机、Git branch/HEAD/worktree、Slurm 状态、依赖、数据、checkpoint 和输出路径。
- Git 非 clean、无法 fast-forward、关键环境/数据/checkpoint 缺失、资源不可用或输出可能被覆盖时，停止并向用户报告证据。

组员项目目录使用：

```text
/gpfs/jiuquyun/projects/<username>/Workspace/Stereo-vison-Tokenizer
```

不要把其他用户的 clone、Git 元数据或本地仓库配置为 origin、alternate 或 fetch source。跨用户数据、模型和 checkpoint 仅在当前任务明确授权的绝对路径下作为只读输入。

## 3. 目录与存储

|路径|可见性|用途|
|---|---|---|
|`/gpfs/jiuquyun/home/$USER`|跨节点共享|个人配置、小型日志|
|`/gpfs/jiuquyun/projects/$USER`|跨节点共享|代码、环境、实验配置、checkpoint 和最终输出|
|`/gpfs/jiuquyun/datasets`|跨节点共享|团队共享数据集；组内可写，修改前确认精确目标|
|`/gpfs/jiuquyun/containers`|跨节点共享|公共容器镜像|
|`/local/cache/users/$USER`|仅当前计算节点|可重建缓存和临时文件|
|KS3|对象存储|归档、备份和跨系统传输|

原则：

- 代码、环境、数据合同、checkpoint 和重要结果放所属项目的 GPFS 目录。
- `/local` 只放可重建缓存和临时文件，不保存唯一 checkpoint 或结果。
- 训练直接引用共享数据集固定路径，不复制整套数据到个人项目目录；组写权限不代表可以覆盖、改名或删除他人正在使用的数据。
- KS3 用于批量归档和搬运，不作为训练逐样本读取层。
- 所有容量都实时查询，不在文档中保存静态总量或带宽数字。

`/gpfs/jiuquyun/checkpoints/$USER` 已废弃；新 checkpoint 与最终结果写入所属项目的 `/gpfs/jiuquyun/projects/$USER` 目录树。

```bash
df -h /gpfs/jiuquyun
du -sh "/gpfs/jiuquyun/home/$USER"
du -sh "/gpfs/jiuquyun/projects/$USER"
```

`/local` 只能在已分配的计算节点中检查：

```bash
srun --jobid=<JobID> --overlap df -h /local
```

## 4. Python 环境

项目优先使用仓库依赖声明和冻结 lock：

```bash
cd "/gpfs/jiuquyun/projects/$USER/Workspace/Stereo-vison-Tokenizer"
uv venv .venv --python 3.11
source .venv/bin/activate
uv sync --frozen
python -V
```

创建或更新环境属于远端写操作，执行前必须获得当前任务授权。不要向系统 Python 或默认 Conda base 安装项目依赖，不使用 `sudo pip install`。

登录、`sbatch`、`srun` 和容器作业中的代理与缓存配置由集群提供，不自行启动、停止或修改系统代理。运行时可检查：

```bash
echo "$XDG_CACHE_HOME"
echo "$HF_HOME"
echo "$TORCH_HOME"
echo "$TRITON_CACHE_DIR"
echo "$CONDA_PKGS_DIRS"
echo "$TMPDIR"
```

缓存应落到当前计算节点的 `/local/cache/users/$USER`；代码、环境、checkpoint 和最终输出仍放 GPFS。

## 5. Slurm 调试与批处理

所有 GPU、训练、评估、预处理及重型 CPU/内存任务都必须通过 Slurm。没有活跃作业时不能直接 SSH 到计算节点是正常的资源隔离行为。

### 最小 GPU 调试

在用户明确授权后，先查询 QOS，再申请满足任务需要的最小资源：

```bash
srun --qos=<qos> --nodes=1 --ntasks=1 --gres=gpu:1 --cpus-per-task=8 --mem=32G --time=00:30:00 --pty bash -l
```

进入分配后检查：

```bash
hostname
nvidia-smi -L
echo "$CUDA_VISIBLE_DEVICES"
exit
```

### 批处理模板

优先复制集群当前模板并检查：

```bash
ls -l ~/slurm-examples/
cp ~/slurm-examples/<template>.sh ./run-job.sh
```

最小结构：

```bash
#!/usr/bin/env bash
#SBATCH --job-name=<job-name>
#SBATCH --qos=<qos>
#SBATCH --nodes=1
#SBATCH --ntasks-per-node=1
#SBATCH --gres=gpu:<gpu-count>
#SBATCH --cpus-per-task=<cpu-count>
#SBATCH --mem=<memory>
#SBATCH --time=<walltime>
#SBATCH --chdir=/gpfs/jiuquyun/projects/<username>/Workspace/Stereo-vison-Tokenizer
#SBATCH --output=/gpfs/jiuquyun/home/<username>/logs/%x-%j.out

set -euo pipefail
source .venv/bin/activate
srun bash scripts/stereo/train_stereo_vae.sh
```

提交前：

```bash
mkdir -p "/gpfs/jiuquyun/home/$USER/logs"
sbatch --test-only run-job.sh
sbatch run-job.sh
```

`sbatch`、`scancel`、交互分配和正式运行都会改变外部状态，只在用户明确授权后执行。

### 单次状态快照

```bash
squeue -u "$USER"
scontrol show job <JobID>
sacct -j <JobID> --format=JobID,JobName,QOS,State,Elapsed,AllocTRES,ExitCode
tail -n 100 "/gpfs/jiuquyun/home/$USER/logs/<log-file>"
```

状态查询遵循 `AGENTS.md` 的单次快照规则。任务取消后用 `squeue` 或 `sacct` 做一次落地核对。

## 6. 多机训练

第一次使用多节点时，先提交只检查节点和 GPU 的小规模作业；确认每个节点的 GPU 可见性和任务拓扑后，再使用项目 launcher。

通用 PyTorch 结构仅作为 launcher 设计参考：

```bash
MASTER_ADDR=$(scontrol show hostnames "$SLURM_JOB_NODELIST" | head -n 1)
MASTER_PORT=<task-port>
export MASTER_ADDR MASTER_PORT

srun bash -lc '
  torchrun     --nnodes="$SLURM_NNODES"     --nproc-per-node=<gpus-per-node>     --node-rank="$SLURM_NODEID"     --master-addr="$MASTER_ADDR"     --master-port="$MASTER_PORT"     <project-entrypoint>
'
```

实际训练优先使用项目已经验证的 Slurm 脚本和 launcher。不要从 H200 配置复制固定网卡、HCA 或 NCCL 参数；H100 网络合同以当前集群和作业实时环境为准。

## 7. 文件传输与 KS3

小文件可使用：

```powershell
scp.exe <local-file> h100:/gpfs/jiuquyun/home/<username>/
```

目录或断点续传使用 `rsync`，传输前确认精确源和目标，不使用 `--delete`：

```bash
rsync -avP -e ssh <local-dir>/ h100:/gpfs/jiuquyun/projects/<username>/<target-dir>/
```

大量数据优先直接在 GPFS 与对象存储之间传输。H100 使用管理员托管凭据的 `h100-ks3`；用户不创建 `~/.ks3utilconfig`，不索取或保存 AK/SK。

```bash
h100-ks3 --help
h100-ks3 ls datasets/<prefix>/ --limit 100
h100-ks3 get <object-path> <local-file>
h100-ks3 put <local-file> <object-path>
```

- Bucket 和 Endpoint 由服务固定，命令只填写对象路径。
- `get`、`put` 默认拒绝覆盖；确认需要覆盖时才显式使用 `--overwrite`。
- 服务不提供删除接口，不手工构造删除请求。

首次传输先用小型非敏感文件验证路径、权限和实际吞吐。任何上传、下载或覆盖都需要当前任务授权。

## 8. 故障取证

|现象|最小检查|
|---|---|
|无法 SSH 到计算节点|确认是否有活跃作业；调试已有作业使用 `srun --jobid=<JobID> --overlap --pty bash -l`。|
|任务一直 PD|用 `scontrol show job` 查看 `Resources`、`Priority`、QOS 和 TRES。|
|QOS/TRES 不合法|重新查询实时 QOS，并用 `sbatch --test-only` 验证脚本。|
|日志无法创建|检查日志目录、`--output`、`--chdir` 和当前用户权限。|
|缓存写入 GPFS|在作业内检查缓存环境变量和 `/local` 可见性。|
|多机初始化卡住|保存 Job ID、节点列表、启动命令和第一条 traceback，不先硬编码网络参数。|
|任务异常结束|读取 `sacct`、exit code、第一条根因错误、最后稳定 step 和关键产物。|
|共享目录异常|立即停止写入，不把正式输出临时改到 `/local` 继续运行。|

报告问题时至少提供：当前用户、Job ID、提交脚本、实际启动命令、QOS/GPU/节点、`scontrol` 或 `sacct` 摘要、日志路径、第一条错误和发生时间。

## 9. 运行边界

- 未经用户明确授权，不创建环境、提交或取消 Slurm 作业、启动训练/评估/预处理、覆盖产物或删除文件。
- 启动前确认精确代码 SHA、clean worktree、resolved config、数据/checkpoint、GPU 资源和唯一 output 路径。
- 不绕过 Slurm，不直接占用计算节点，不修改系统代理、调度、存储或监控服务。
- SSH 连接中断、等待失败或返回缺失时，先只读核对操作是否落地；只有确认未落地且重试幂等时才能继续。
- 当前 Git、Slurm、进程、日志和结果文件优先于本文及历史实验记录。
